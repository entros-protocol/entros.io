Render `<EntrosVerify />` as a button in your React tree. The user connects a wallet and completes the capture inside a popup. The `onVerified` callback reports a completed Entros verification.

This is the **Tier 1 drop-in path**, the right choice for around 90% of integrations and the one to reach for whenever the gated action is worth the friction. To read an existing Anchor instead, for display or a lower-stakes gate, see the **Tier 3 path** in [Next.js: gate a route](/docs/quickstart/next-js).

## Install

```bash
npm install @entros/verify
```

The package declares `react ^19` and `react-dom ^19` as peer dependencies. No Solana adapter, no SDK, no web3.js install on your side—those live behind the popup boundary on entros.io.

## Five-line usage

```tsx
import { EntrosVerify } from "@entros/verify";

<EntrosVerify
  integratorKey="your-integrator-key"
  onVerified={(result) => grantAccess(result.walletPubkey)}
/>
```

On click: a popup opens to entros.io, the user connects their wallet, completes the 12-second capture, signs the on-chain verification transaction (a first-time `mint_anchor` or a returning-user `update_anchor`), and the popup posts the verified payload back via `onVerified`. The component renders a single `<button>`; style it with `className` or `style`.

## The verified payload

```ts
interface EntrosVerifyResult {
  walletPubkey: string;       // Base58 Solana wallet address
  attestationPda: string;     // Derived SAS address. Check whether the account exists
  txSig: string;              // Confirmed transaction signature
  trustScore: number;         // On-chain Trust Score after this verification
  cluster: "devnet";
}
```

`walletPubkey` identifies the wallet. `trustScore` lets you apply an application policy. `txSig` identifies the confirmed verification transaction. `attestationPda` is the deterministic address where a best-effort SAS issuance can appear. Fetch the account before treating the attestation as issued.
